# Yumma — two-minute competition demo recording guide

**Required format:** a recording of the running AI agent, participant webcam overlay visible in a corner, and spoken explanation. **Maximum duration: 120 seconds.** This guide is not itself a completed recording.

## Recording setup
1. Use Node.js 20 or later. From the project root run `npm run verify`, then `npm start`.
2. Open `http://127.0.0.1:4173` in a desktop browser.
3. Use only the preloaded synthetic Salma scenario. Do not enter real personal, banking, health or family data.
4. Record the browser window and participant webcam in a small, unobtrusive corner overlay. Keep the agent interface readable.
5. Capture one continuous take if possible. If editing, do not fabricate clicks, results, integrations or system behaviour.

## Time-coded live demo

| Time | What must be visible | Suggested narration |
|---|---|---|
| 0:00–0:12 | Yumma browser interface, emerald Abaya hologram concept and `LOCAL SYNTHETIC DEMO` label | “Meet Yumma, a personal life-intelligence AI agent. She helps people pause, understand pressure and make their own decisions.” |
| 0:12–0:28 | Judge demonstration mode; select `bank-transfer-pressure`; run the scenario | “This is a synthetic bank-impersonation request. The caller creates urgency, asks for a transfer and tells the person to keep it secret.” |
| 0:28–0:55 | Actual result: risk signals, protection posture and recommended next step | “Yumma connects the signals and moves to Pause and Protect. She explains why independent verification matters. This is a deterministic local prototype—not a live bank connection.” |
| 0:55–1:12 | Show policy decision, audit/evidence details and explicit no-external-action boundary | “The safety policy does not authorise a transfer or any external action. The person remains in control. A remembered commitment can guide a pause, but never grants authority.” |
| 1:12–1:32 | Select `benign-information`; run it; show `INFORMATIONAL` posture | “Yumma also needs to avoid unnecessary alarm. Here, a benign banking information request stays informational rather than triggering a high-risk intervention.” |
| 1:32–1:52 | Show verification evidence: 64 tests, four synthetic scenarios; keep caveat visible | “The local verification run passes 64 automated tests and all four synthetic judge scenarios. These are engineering tests, not real-world fraud accuracy or independent security certification.” |
| 1:52–2:00 | Return to Yumma welcome/closing screen | “Yumma helps people keep their choices, their dignity and their independence.” |

## Final recording checklist
- [ ] Participant webcam overlay visible throughout, as required by the organiser.
- [ ] Actual running browser agent shown; no cinematic-only montage substituted for the working demo.
- [ ] Both high-risk and benign cases are actual runs in the interface.
- [ ] Spoken explanation is audible and matches what is on screen.
- [ ] Synthetic-only data is clearly labelled; no real personal or banking information appears.
- [ ] No claim of live bank, payment, messaging, 3D hologram or live model integration.
- [ ] Captions are readable; audio is clear; final MP4 is 120 seconds or less.
- [ ] Play the exported MP4 from beginning to end and confirm the webcam overlay, audio and captions survived export.

If the Calm-State Contract cannot be demonstrated clearly in the live UI within the time limit, describe it as a designed capability supported by the local prototype's consent/recall tests; do not imply that it was shown live in the recording.
